## 2. 英文版（若投外企/合资）

**Raven — Black-Market Content Detection for Gaming Communities** | Independent project

- Built a three-stage pipeline (adversarial text normalization → char n-gram hybrid classifier → tiered moderation)
  for four black-market content types; created a 2,000-sample labeled dataset with disjoint train/test templates
  and 8 controllable obfuscation operators.
- Normalization lifted keyword-rule F1 from **0.000 to 0.889** under per-character-separator evasion;
  the fused model holds **0.93–0.95 F1** across four adversarial test sets (AUC 0.984).
- Tiered decision policy: auto-block tier covers **83.9%** of violations at **1.000 precision**; 0.46 ms per item on CPU.
- Image side: ELA + noise-residual + JPEG-ghost block features for tamper triage (AUC 0.973) with localization heatmaps;
  ablation showed ELA to be near-useless, so the feature set was pruned accordingly.

## 3. 面试问答（10 问，含最尖锐的几个）

**Q1：这个项目最难的地方是什么？**
不是模型，是**让指标可信**。第一版跑出来几乎所有配置都 0.99+，我第一反应是"数据有问题"——
查下去发现训练集和测试集共用同一批模板，模型记的是句式。把模板按类别切开、1/3 只用于测试之后，
分数掉到 0.88~0.94。**分数太好的时候，先怀疑数据。**

**Q2：数据是你自己造的吧？那这些指标有什么意义？**
有意义，但不是"效果意义"，是"方法意义"。它证明的是：在给定变形空间里，
这套架构的哪一层在起作用、哪一层是摆设。所有结论我都标注了合成数据和变形手法的边界。
真实数据接进来，同口径指标一定会掉，我在报告的第 8 节把这句话写在最显眼的位置。

**Q3：为什么不用 BERT？**
两个原因。一是 660 条训练样本微调大模型必然过拟合；二是项目要求 clone 下来一条命令能跑，
不能要求装 torch。更重要的是我做过对比：字符 1~3 gram 在"逐字符插入"这类攻击下天然鲁棒
（F1 0.942），因为它的特征是"哪些字出现过"，插字符打不断它。BERT 能不能更好我不知道，
但我现在这套的成本是 9 秒训练、0.46ms 推理。

**Q4：那你的系统最大的漏洞在哪？**
语境。误报几乎全是"提到黑产词但语境是举报"的样本，比如"提醒大家别信那些代练工作室，我被坑了298块"。
词袋模型分不清"这个词是被卖的，还是被骂的"。这个洞加词表补不上，得上语义理解——
所以我把 LLM 复核排在路线图第一位，而且只跑灰区（0.40~0.82），调用量很小。

**Q5：为什么设两个阈值？**
判决阈值（0.38）只用来算指标，把各配置拉到同一水平线比较；处置阈值（0.82/0.68/0.40）才是真正做什么。
因为"判违规"和"自动拦截"的置信度要求完全不同——误伤一个正常用户，比漏掉一条广告贵得多。
这两个分开之后才能出分档表：自动拦截 151 条、精确率 1.000、覆盖 83.9%，漏掉 4.4%。

**Q6：你提到过一个 AUC 0.99 但是没用的模型？**
对，这是我最想讲的坑。AUC 0.99，但分数全挤在 0.45~0.65，按 0.82 分档一条都进不去。
根因是学习率衰减系数写大了（0.15），120 轮后学习率只剩 5%，权重没长起来。
**AUC 只衡量排序，不衡量校准。** 凡是靠阈值做决策的系统，必须单独看输出分布。

**Q7：图像侧为什么可信度更低？**
因为数据是程序化生成的海报，噪声模型比真实照片简单得多。AUC 0.973 只说明"方法链路通了"，
不说明"能上生产"。还有一个更具体的证据：定位命中率只有 0.304——检测对了不代表框对了，
所以我把它定位成"粗筛 + 指给人工看"，不是终审。
另外消融显示 ELA 在这批数据上 AUC 只有 0.60，接近随机，原因是篡改素材被平滑过、
噪声能量是**下降**的，而 ELA 只会看"哪里误差变大"。这一步逼我把 ELA 从判决特征降级为可视化证据。

**Q8：这个项目里 AI 帮了你多少？**
实现层面大概 70%，判断层面 0%。具体说：代码、模板、文档初稿基本都是 AI 出的；
但"模板必须隔离""变形必须逐词条而不是只改一个词""必须看输出分布而不只看 AUC"
这三条判断是我出的，而它们恰好决定了这个项目的数字是真还是假。
我给 AI 的验收清单有 8 条，每条都对应一次真实的翻车（详见 `docs/AI_COLLAB.md`）。

**Q9：如果让你上线到真实社区，第一步做什么？**
先跑影子模式两周：只记录不处置，把分数分布和人工复核结论对齐，
用真实数据重新定阈值——因为合成数据算出来的 0.82 在真实分布上一定是错的位置。
第二步才是接入灰区的 LLM 复核。第三步是图片化文本的对抗（把广告做成图片发），
这是纯文本方案最大的盲区。

**Q10：你觉得这个项目和你简历上其他项目什么关系？**
它是把前面几块串起来的那一环。FUSED 让我知道深度取证模型的能力边界，
所以我知道图像侧该做粗筛而不是硬上检测器；大创里的 LLM + CodeQL 让我知道 LLM 适合做语义判断、
不适合做高召回的一线过滤，所以我把 LLM 放在灰区复核；B 站运营让我真的见过外挂代练账号交易
的文案长什么样——数据集的 120 条模板不是编的，是从真实话术里抽的骨架。

## 4. 面试时怎么演示（3 分钟版本）

1. 打开 `demo/index.html`，点样例「逐字符分隔绕过」或输入 `出·原·神·外·挂·加·薇·信`
   —— 归一化流水线一步步把它折叠回 `出原神外挂加微信`，分数 **0.964**
   （同一句不折叠只有 **0.087**，差 11 倍），进拦截档。
2. 再输入 `今天在群里看见有人卖原神外挂，已经举报了`
   —— 分数 0.014，放行。顺势讲"否定语境"和"这是词袋模型的硬伤"。

> 分数的出处是可复算的：`python -m raven.cli` 或页面右上的实时分值。
> 别凭记忆报数——**0.805 是早期版本的残留值，已经删掉**。
3. 打开 `report.html`，直接翻到分档表
   —— "自动拦截档精确率 1.000，覆盖 83.9%"。
4. 最后一句话收尾：**"这个系统我最满意的不是 0.93，是我知道它在哪 8 条上会错。"**
