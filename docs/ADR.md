# 决策记录（ADR）

每条都写清楚：背景、选了什么、放弃了什么、什么时候应该推翻它。
最后一节记的是**被我自己推翻的方案**——这部分往往比结论有用。

---

## ADR-001 用合成数据，不爬真实社区数据

**背景**：项目要算指标，就必须有真值。真实社区数据涉及隐私与平台条款，既拿不到也不好分发。

**决定**：模板 + 槽位 + 可控变形算子自造数据集，变形手法逐条记录。

**放弃**：真实感（分布偏移、长尾表达、真实用户画像）。

**代价与缓解**：所有结论都标注"合成数据"；专门加 `test_holdout` 测"词表外变体"，
给这个假设的上限画一条线。真实数据接入后，这四列同时保持才算结论成立。

**什么时候推翻**：拿到合规的真实标注数据后，第一件事就是在这批数据上重跑，看落差有多大。

---

## ADR-002 手写 SGD，不用 sklearn / torch

**背景**：环境要可复现。评审方（或面试官）clone 下来应该一条命令能跑。

**决定**：`numpy` 手写逻辑回归，FNV-1a 哈希特征，权重导出成 JSON。

**放弃**：开箱即用的调参工具、更复杂的模型。

**收益**：
- 训练 5 秒，纯 CPU，无 GPU、无网络；
- 权重能被浏览器完整复现（对拍最大概率差 5e-5）；
- 每一行梯度我都能解释，这比 import 一个黑盒更能应付追问。

**什么时候推翻**：样本量上到万级、或需要语义理解时。那时线性模型的瓶颈是表达力，不是工程。

## ADR-003 归一化放在判决之前，且与变形生成器共用同一张词表

**背景**：最自然的做法是"多准备一些正则"。但变形手法无穷，正则有穷。

**决定**：先做语义等价折叠（10 步流水线），让下游只认识一种写法。
词表同时被生成器（正向变形）和归一化层（反向折叠）使用。

**放弃**：更"干净"的评测独立性。

**风险（我自己标出来的）**：共用词表构成隐含的循环论证——我造出来的变形，恰好是我能还原的。
所以必须有 `test_holdout`：用归一化词表里**没有**的谐音变体测，那一列（0.946）才是这套方法的下限。

**踩过的坑**：第一版流水线是"谐音折叠 → 折叠分隔符"，顺序反了。
`薇·信` 被分隔符切开，谐音表里只有 `薇信`，永远匹配不上。这个 bug 在干净集上完全看不见，
只有逐字符分隔的样本会暴露——这就是为什么要专门造 `test_pervasive`。

## ADR-004 判决用字符 n-gram，不用分词 + 预训练模型

**背景**：黑产文本天然破坏分词（插符号、拆字），分词器的错误会直接传导到特征。
而 660 条样本微调 BERT 必然过拟合。

**决定**：字符 1~3 gram + 哈希 + 线性模型。规则分作为**附加特征**喂进去（10 维，可解释）。

**放弃**：语序、否定、指代——所有需要上下文理解的能力。

**代价**：误报几乎全集中在"举报语境"，这是原理性的。已在路线图里给了解法（LLM 复核灰区）。

**为什么规则分要当特征而不是直接融合**：直接把 `p = α·model + (1-α)·rule` 融合，
α 需要调，而且规则分在对抗样本上整体偏低时会拖累模型；
当特征喂进去，模型自己学"什么时候该信规则"，权重还能被读出来解释。

## ADR-005 判决阈值与处置阈值分成两套

**背景**：做评测需要一个统一阈值来横向比较各配置；但真正做处置时，
"判违规"和"自动拦截"的置信度要求完全不同——误伤一个正常用户比漏掉一条广告贵得多。

**决定**：判决阈值（0.38，只在 val 上选，只用于算指标）；处置阈值（0.82 / 0.68 / 0.40，
由"误报率上限反查"得到，用于真正做什么）。

**收益**：能出分档表。"自动拦截 151 条、精确率 1.000、覆盖 83.9% 违规"
这句话比"F1 = 0.930"有信息量得多，也更能对上业务语言。

**什么时候推翻**：如果业务接受"宁可错杀"，那 0.63 的工作点（召回 0.917 / 误报 4.4%）更划算。

## ADR-006 图像侧只做粗筛，不直接上深度取证

**背景**：我复现过 FUSED（ICME 2026），知道深度取证模型的精度上限在哪。
但它的成本、不可解释性、以及"换一批数据就失效"的风险，都不适合做第一道。

**决定**：ELA + 噪声残差 + JPEG ghost 的块级统计特征，逻辑回归判决，
输出**定位热力图**供人工复核。定位是产品需求（"指给我看哪里被改了"），不只是技术指标。

**放弃**：像素级精度（现在定位命中率只有 0.304）。

**关键设计**：必须有 `clean_resaved` 硬负样本，否则模型学的是"有没有被二次压缩"。
代价是 7.7% 的误报，但这是诚实的价格。

**什么时候推翻**：真实照片场景下，统计特征的天花板会很快撞到，那时接 FUSED 做第二级。

## ADR-007 demo 在浏览器里重实现一遍推理，并对拍

**背景**：demo 最容易变成"截个图骗人"。声称"这就是同一套模型"如果不验证，就是营销话术。

**决定**：把权重导出成 JSON 内嵌页面，用 JS 重写归一化 + 特征 + 模型，
再用 `tools/parity_test.py` 拿 225 条样本与后端逐条对比概率。当前最大差 5e-5，归一化结果 0 条不一致。

**代价**：两套实现，改一处要同步两处。

**缓解**：对拍脚本进 `run_all.py`，同步问题会在 CI 里直接暴露，而不是被人发现。

## 被推翻的方案（更值得看）

### ✗ 方案 A：只对关键词做变形，测"鲁棒性"

第一版数据集每条只变形**一个**词条。结果连"规则·原始文本"都拿到 0.937，
整张消融表看起来"各方案都很稳"。

**为什么错**：剩下 90% 的原文仍是强信号，我测的是"变形 1 个词有多大影响"，
不是"变形能不能绕过检测"。

**改成**：逐词条施加（概率 0.7）+ 新增整句逐字符分隔集。① 立刻掉到 0.000。

### ✗ 方案 B：直接把规则分和模型分加权融合

`p = α·p_model + (1-α)·p_rule`，α 在验证集上搜。

**为什么错**：搜出来的 α 极不稳定，且融合值是两者"折中"，两个信号互相拖累。
在早期版本里，融合后的对抗集 F1 比纯字符模型低 0.045。

**改成**：规则分当**特征**喂进模型，让模型学条件权重。最终四套测试集无短板。

### ✗ 方案 C：只报 F1 和 AUC

模型 AUC 0.99，报告很漂亮。但分档表一拉，"自动拦截"是 0 条——输出全挤在 0.45~0.65。

**为什么错**：AUC 只衡量排序，不衡量校准。排序对了 ≠ 概率能用。

**改成**：训练收敛重调（学习率衰减 0.15 → 0.01），并把**分档表**作为报告的主表，
F1 退居其次。

### ✗ 方案 D：在工作区根目录直接写文件

**为什么错**：项目会越滚越乱，`artifacts/` 里的中间产物和源码混在一起，
别人 clone 下来分不清哪个是入口。

**改成**：`raven/`（库）、`data/`（造数）、`eval/`（评测）、`tools/`（构建）、
`demo/`、`docs/`、`artifacts/`（全部可再生）分层，`run_all.py` 是唯一入口。
