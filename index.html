Raven
游戏与二次元社区内容风控引擎

社区里有人发 出·原·神·外·挂·加·薇·信，或者把「外挂」写成「外褂」、 中间夹零宽字符、用全角字母拉开——关键词规则一条都打不中。

这个项目做的是：先把语义等价的写法折叠成规范形，再用字符级模型判决， 最后按置信度分级处置。纯 CPU、无外部 API、无网络依赖， 一条命令复现全部指标。

三个比数字更值钱的发现

逐字符分隔能把关键词规则打到 F1 = 0.000

出·原·神·外·挂 这种最土的绕过，规则层一条都检不出。 归一化之后回到 0.889，但字符 n-gram 模型天生免疫这类攻击—— 说明归一化的价值取决于判决层依赖什么，不是一律加分。

规则层与模型层的失败样本几乎不重合

所以融合后没有短板，四套测试集没有一套低于 0.93。 消融阶梯在报告里逐级列出，不是只报最后一档。

模型排序对了，不等于概率可用

第一批模型 AUC 0.99，但输出全挤在 0.45~0.65，分档阈值形同虚设。 只看 AUC 的评测永远发现不了这个问题——这也是后来加分档表的原因。

边界

⚠ 先说清楚，免得被问到
  • 数据是合成的：模板 + 槽位 + 可控扰动。真实社区分布更脏，同口径指标一定会掉。
  • 变形手法是自造的 7 类 + 1 类未登录谐音，真实黑产花样更多。
  • 训练样本 660 条，F1 置信区间约 ±0.03，消融之间零点几的差距不该当结论。
  • 图像侧只在程序化海报上验证，说明"链路通了"，不说明"能上生产"。
  • 上下文理解是原理性硬伤：误报集中在"举报语境"（提到黑产词但在举报 / 避雷）。
